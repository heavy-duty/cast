### 2. The consumer's shape through the shipped binary (the headline feature)

The shape heavy-duty/la-familia-site#211 will declare — the admin as a Docker
Image application that nginx reaches by the alias `api`:

```yaml
admin:
  image: { name: ghcr.io/acme/admin, tag: stable }
  build: { pack: dockerimage }
  port: 8787
  healthcheck: /api/health
  network_aliases: [api]
  domains: []
```

run through `dist/cli.js` of this tree against a **stub** Coolify
(`test/network-aliases-cli.test.ts`, three cases, all passing on this tree):

| leg | result |

## Waived

**The A→B promotion on two live Coolify instances** is **waived**, as it was
for 0.3.0 and 0.4.0: the box reaches no Coolify, and cast still has no drill
harness of its own (#141, #142).

What this release therefore does not prove, stated so it is not rediscovered:

- that Coolify 4.1.2 **accepts** `custom_network_aliases` as cast sends it, a
  comma-joined string, on create and on PATCH. Read off
  `ApplicationsController.php` at v4.1.2 (the create allowlist `:914`, the
  PATCH allowlist `:2368`), not run against an instance;
- that the alias reaches the container on the next deploy, so that a sibling
  resource resolves it on the destination network.

The consumer's staging covers both: la-familia-site's `admin` declared with
`network_aliases: [api]`, applied, and nginx reaching it at `http://api:8787`.
